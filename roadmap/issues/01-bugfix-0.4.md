# 0.4: fix field registration, lifecycle and CI issues

Labels: `bug`

Part of the roadmap tracking issue. **Non-breaking**: ships on the 0.x line before v2 work starts.

## Bugs

- [ ] **A class registered directly is detected as a lazy factory.** `isLazyFactory()` (`src/forms/create-field.ts:26`) checks `factory.length === 0`, which is also true for subclasses without an explicit constructor. The class gets called as a function, throws `Class constructor … cannot be invoked without 'new'`, and the form controller drops the field with only a `console.warn`. This breaks Step 5 of the custom-fields guide.
  - Fix: add `lazy(() => import(...))` as an explicit marker. Keep the arity check only as a fallback for unmarked functions that are not classes (check `/^class[\s{]/` on `Function.prototype.toString`, or check that `prototype` is an `AbstractDomFormField`).
- [ ] **Lazy fields ignore `fieldOptions`** (`src/forms/form-controller.ts:249`). Pass `fieldOptions: this.fieldOptions` to `createFieldAsync`.
- [ ] **No ready signal.** Add `FormControllerApi.ready: Promise<void>`, which resolves once every pending lazy field and form plugin has loaded. The submit handler awaits `ready` before validating, so lazy fields are no longer skipped.
- [ ] **`FileSize` doesn't work in custom fields.** `AbstractDomFormField.validate` passes `{}` (`src/forms/abstract-dom-field.ts:193`). Pass `__files` when the control is `input[type=file]`, the same way `FieldController` does.
- [ ] **The generic `finish()` doesn't unregister the form** (`src/forms/form-controller.ts:356`). Notify the registry, for example through an `onDestroy` callback the registry passes in, so that `formRegistry.get(id)` stops returning a destroyed controller.
- [ ] **Async validators are skipped.** For 0.4, log them with `console.error` instead of `warn` and document the limitation. The real fix is in the validation-pipeline issue.
