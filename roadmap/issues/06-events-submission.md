# v2: DOM events, submission result, form-level errors, plugins

Labels: `enhancement`, `breaking`

Part of the roadmap tracking issue. Depends on the field-core issue. Can run in parallel with the validation work.

## Problem

- Events only exist on an internal bus, so vanilla-JS integrators can't use `addEventListener`.
- `on()` has no unsubscribe, and there's no way to cancel a submit before it happens.
- Errors can only belong to a field. TYPO3 spam and finisher errors have nowhere to go.
- The submit flow and its JSON shape are TYPO3-specific.
- Forms require an `id`, and plugins must be lazy loaders without options.

## Scope

- [ ] **DOM events**, bubbling from the field wrapper or the form:
  - `formlayer:field-change`, `formlayer:valid`, `formlayer:invalid`;
  - `formlayer:before-submit` (cancelable), `formlayer:submit-result`, `formlayer:loading`, `formlayer:reset`.

  Typed through `HTMLElementEventMap` augmentation. Custom fields can dispatch their own typed events through `ctx`.
- [ ] Keep the internal bus. `on()` / `once()` return an unsubscribe function.
- [ ] **A standard submission result** `{ fields, form, redirect?, html?, finished?, state? }`. Add `ctx.applyResult(result)` next to the existing helpers. The TYPO3 adapter maps its JSON onto this shape.
- [ ] `FormState.formErrors: string[]`. A default form-error renderer (`[data-fl-form-errors]` container) that can be overridden.
- [ ] Controllers are stored in a `WeakMap<HTMLFormElement, …>`. `formSelector` defaults to `form` (no `id` required). `get(idOrElement)` keeps working.
- [ ] **Plugins:** accept a plugin object or `lazy()`, plus options (`registerFormPlugin(plugin, options)`), plus submit hooks: `beforeValidate`, `transformFormData`, `afterSubmit`.
- [ ] **Focus after a swap** (C9, M2):
  - after `finish()`, move focus to the confirmation (`[data-form-success]`, or the new element given `tabindex="-1"`);
  - after a step swap, move focus to the new step's heading (the first `h1`–`h6`, or `[data-fl-step-heading]`).
- [ ] The TYPO3 adapter maps `errors.__form` (and the empty-string key) to `formErrors` (C8).
- [ ] Remove the deprecated `submitTypo3Form`.
- [ ] Docs: update the events guide with DOM-event examples for integrators.

## Acceptance criteria

- `form.addEventListener('formlayer:invalid', …)` works without importing FormLayer.
- `event.preventDefault()` on `formlayer:before-submit` stops the submit.
- A form without an `id` is enhanced.
- A TYPO3 error that isn't tied to a field shows up in the form error container.
- Playground checks C8, C9 and M2 pass.
