# v2: unified field core and `defineField()`

Labels: `enhancement`, `breaking`

Part of the roadmap tracking issue. Depends on the 0.4 bugfix release.

## Problem

`FieldController` and `AbstractDomFormField` each implement validation, server errors, enable/disable and reset (about 200 duplicated lines), and they have already drifted apart (see the `FileSize` bug). Writing a custom field means knowing:

- the two-phase `init()`;
- `!` and `declare` on class fields;
- `setControlElement()`;
- the right order of `markDirty` / `markTouched` / `validate` / `notifyChange`.

## Scope

- [ ] A single internal `BaseField` owns state, validation, server errors, enable/disable, the error presenter and events.
- [ ] `NativeField` (today's `FieldController`) becomes a thin adapter on `BaseField` for input/select/textarea, checkbox and radio groups, and file inputs.
- [ ] `defineField({ setup(ctx) })` is the public authoring API:
  - `ctx`: `wrapper`, `name`, `signal`, `part<T>(name)` (finds `[data-fl-part="name"]`, falling back to the first control), `commit()` (the user changed the value: marks it dirty, validates according to the trigger, notifies), `touch()` (marks it touched and validates).
  - `setup` returns `{ read, write, focus?, reset?, destroy? }`.
- [ ] Explicit registration: `registerFieldType(type, Field)` or `registerFieldType(type, lazy(() => import('./x')))`. Remove the arity detection.
- [ ] Value model: `FieldValue = string | string[] | File[]`. Validators get the typed value. Multi-selects and checkbox groups are no longer joined with commas.
- [ ] Lifecycle names follow the browser's form-associated custom elements API (reset, disabled, validity), so the concepts transfer.
- [ ] Core exports a small auto-escaping `html` tagged template (returns a `DocumentFragment`) for render hooks.
- [ ] `AbstractDomFormField` stays for one minor version as a deprecated shim that wraps `BaseField`, then is removed.
- [ ] Port the date-picker and ALTCHA plugins to `defineField`.
- [ ] Docs: rewrite the custom-fields guide around `defineField` (the image-preview example).

## Out of scope

- Public subclassing or `.extend()` of plugin fields.
- Stimulus-style targets and values beyond `ctx.part()`.
- Field "behaviours" (`data-behaviors`).

## Acceptance criteria

- The image-preview field from the docs fits in no more than about 40 lines with `defineField`, without `!` or `declare`.
- The existing `FieldController` and `AbstractDomFormField` test suites pass against `NativeField` and the shim.
- Date-picker and ALTCHA work unchanged in the demo.
