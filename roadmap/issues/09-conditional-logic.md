# Conditional logic: groups, chained conditions, no flash on load

Labels: `enhancement`, `plugin-client-variants`

Part of the roadmap tracking issue. Depends on the field-core issue, and on sync plugin support from the events/submission issue. Found by the playground (`03-conditional`, `02-address`).

## Problem

| Check | Finding |
|---|---|
| A2, A3 | `data-client-variants` only works on `[data-form-field]` wrappers. A condition on a fieldset ("ship to billing address" → hide the shipping address) is ignored, so the group stays visible and its required fields block the submit. Today the integrator has to repeat the condition on every field. |
| K4 | A hidden field keeps its value inside conditions. Unticking "company" hides "company size", but "account manager" (which depends on company size) stays visible. |
| K6 | The conditions plugin is lazy-loaded after `DOMContentLoaded`, so conditional fields flash visible on every page load. |

## Scope

- [ ] **Group conditions:** `data-client-variants` on any container inside the form (fieldset, section). The container gets `hidden`, and every field inside it is disabled (left out of validation and `FormData`). This needs a host API: `host.getFieldsIn(element)` / `host.setFieldsEnabled(names, enabled)`.
- [ ] **Hidden means empty:** `formValue("x")` returns `''` for a disabled or hidden field.
- [ ] **Evaluate to a fixpoint:** re-evaluate until nothing changes (with a guard against cycles), so chains of any length settle in one pass.
- [ ] **No flash:**
  - the plugin can be registered synchronously and evaluates during `init()`, before first paint;
  - plus a documented CSS fallback for lazy setups (`[data-client-variants]:not([data-fl-evaluated]) { visibility: hidden }`).
- [ ] Keep server parity: the TYPO3 `ClientVariantsValidationListener` already disables fields server-side. Document that group conditions need the same treatment there.
- [ ] Optional: when a condition reveals content, keep focus where the user is (no focus jumps). Document `aria-controls` on the controlling input.
- [ ] Docs: a conditional-fields guide using the playground examples.

## Acceptance criteria

- Playground checks A2, A3, K4 and K6 pass.
- K1, K3 and K5 still pass.
