# Repeatable field groups

Labels: `enhancement`

Part of the roadmap tracking issue. Depends on the field-core, validation-pipeline and events/submission issues. Found by the playground (`04-repeatable`).

## Problem

FormLayer already picks up rows that are added or removed (R1–R3) and maps per-row server errors (R4). Everything else is integrator code: 38 lines in `playground/src/integrator/repeatable.ts` (R5). That covers adding rows from a `<template>`, numbering, min/max limits, hiding the controls without JS, moving focus, and announcing changes. Group limits ("1 to 5 participants") can't be validated on the client at all.

## Proposed markup

The same as the playground, with `data-fl-*` names:

```html
<section data-fl-repeatable="participants" data-min="1" data-max="5"
         data-validate='[{"type":"Count","options":{"minimum":1,"maximum":5}}]'>
  <div data-fl-repeatable-list>…server-rendered rows…</div>
  <template data-fl-repeatable-template>…row markup with __INDEX__…</template>
  <button type="button" data-fl-repeatable-add hidden>Add participant</button>
</section>
```

## Scope

- [ ] Built-in repeatable behaviour (in core or as a small plugin without dependencies):
  - add and remove rows;
  - `__INDEX__` replacement, with a monotonically increasing index (the server must accept gaps);
  - renumbering of `[data-fl-repeatable-number]`;
  - min/max on the add and remove buttons;
  - add/remove buttons are hidden until enhanced, so no-JS users get the server-rendered rows.
- [ ] Focus: the first control of a new row; after a removal, the next row or the add button.
- [ ] Announce "Participant 2 added/removed" through the page's live region (see the CSS/error-summary issue).
- [ ] **Group as a field:** the group registers as a field (value = number of rows), so group rules (`Count`) and server errors keyed by the group name (`participants`) have a place to render.
- [ ] Events: `formlayer:row-added` and `formlayer:row-removed` (cancelable before removal).
- [ ] TYPO3: document how a repeatable container maps to EXT:form (for example via a repeatable-container extension), and the expected server error keys.

## Acceptance criteria

- Playground scenario `04-repeatable` works with **no** integrator script.
- A new playground check covers the group `Count` rule.
