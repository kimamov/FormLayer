# Playground findings

What the playground scenarios show about FormLayer 0.3.x. The check IDs refer to [CAPABILITIES.md](CAPABILITIES.md) (generated by `npm run playground:check`). Each finding names the GitHub issue that covers it (all are sub-issues of [#5](https://github.com/kimamov/FormLayer/issues/5)).

**Result: 16 of 40 checks passed on 0.3.x. With the 0.4 fixes (#6) 23 of 40 pass.**

## What already works

- Dynamic fields: rows added from a `<template>` register automatically and are validated, and removed rows unregister (R1–R3).
- Nested names (`billing[city]` with `data-form-field="billing.city"`) and server errors keyed by dotted paths, including repeatable rows (`participants.1.email`) (A1, A4, R4).
- Server-only errors after submit, and server errors on later steps of a multistep form (C7, M4).
- Multistep forms rendered by the server are swapped in and re-enhanced (M1).
- Conditional fields driven by the *first* radio option or a select, and hidden fields stay out of validation and submission (K1, K3, K5).
- Focus moves to the first invalid field after a failed submit, and errors are linked with `aria-describedby` (C4).
- `FileSize` on native file inputs (W5).

## Bugs (fixed in 0.4 → [#6](https://github.com/kimamov/FormLayer/issues/6))

All four are fixed in 0.4; checks C2, C10, K2, M3, W1, W2 and W6 now pass. The group listeners use the capture phase on the field wrapper rather than `focusout`, so synthetic non-bubbling events (`new Event('change')`) dispatched by integrator code keep working.

| Finding | Checks | Cause |
|---|---|---|
| **Radio and checkbox groups only react to their first control.** Clicking the 2nd option directly doesn't update the value, so conditions that depend on it never fire. | C10, K2, W2 | `FieldController.bind()` adds `input`/`change`/`blur` listeners to `this.input` (the first control) only. It only *seems* to work when the first option was focused before, because that option's `blur` fires. Fix: listen on the wrapper (`change` and `input` bubble; use `focusout` instead of `blur`). |
| **Back buttons with `formnovalidate` are blocked by client validation.** | M3 | The submit handler always validates. Fix: skip validation when `event.submitter?.formNoValidate` is true. |
| **`required` is removed from inputs**, so screen readers no longer announce "required". | C2 | `disableNativeValidation()` strips `required`, `pattern`, … even though the form already has `novalidate`. Fix: keep the attributes in the form path; when they must be removed (standalone fields), set `aria-required="true"`. |
| **TYPO3 `Count` and `MimeType` rules are unknown**, so they silently pass. | W1, W6 | Missing validators. Every TYPO3 core validator needs a client equivalent or `"server": true`. |

## Accessibility gaps (web.dev / modern-web-guidance form rules)

| Finding | Checks | Issue |
|---|---|---|
| An error appears on the first blur of a field the user never typed in. The guidance is to validate on blur only once the field was edited, and on submit. | C1 | [#9](https://github.com/kimamov/FormLayer/issues/9) (trigger defaults) |
| Controls don't start with `aria-invalid="false"`. Firefox and Safari then announce empty required fields as invalid before any interaction. | C3 | [#8](https://github.com/kimamov/FormLayer/issues/8) (error presenter) |
| Field errors that appear on blur are not announced. The guidance is one polite live region per page. | C5 | [#13](https://github.com/kimamov/FormLayer/issues/13) (error summary and live region) |
| Group errors (radio, checkbox) are linked to the first control only. They should be linked to the `fieldset`. | C11 | [#8](https://github.com/kimamov/FormLayer/issues/8) |
| After a successful AJAX submit the form is replaced and focus falls back to `<body>`. | C9 | [#11](https://github.com/kimamov/FormLayer/issues/11) |
| After a multistep step change, focus falls back to `<body>`. It should move to the new step's heading. | M2 | [#11](https://github.com/kimamov/FormLayer/issues/11) |

## Notes for the docs

- Error containers must **not** be referenced from `aria-describedby` in the markup. FormLayer adds the reference only while the field is invalid, which is correct. Documented markup examples should follow this.
- Fields hidden through the `hidden` attribute need `[hidden] { display: none !important; }`, otherwise layout rules such as `.field { display: flex }` keep them visible. `base.css` ([#13](https://github.com/kimamov/FormLayer/issues/13)) should ship this rule.
- In `formlayer/forms.css`, invalid text inputs never get the red border, only textareas do: `[data-form-field] input:not(…)` is more specific than `input.is-invalid`. Covered by [#13](https://github.com/kimamov/FormLayer/issues/13) (zero-specificity `:where()` rules).
- `formlayer/forms.css` only works after defining `--accent`, `--bg`, `--text`, … (see `playground/src/playground.css`). This is already covered by [#13](https://github.com/kimamov/FormLayer/issues/13).
